# 01 软件包与包管理器基础

## 1.1 什么是 Linux 软件包

软件包英文叫 **Package**。它不是单独一个程序，而是把一个软件运行需要的内容打包起来，通常包括：

- 可执行程序：例如 `/usr/bin/vim`、`/usr/sbin/nginx`
- 动态库文件：例如 `.so` 文件
- 配置文件：例如 `/etc/nginx/nginx.conf`
- 服务文件：例如 systemd 的 `.service` 文件
- 文档文件：例如 man 手册、README
- 元数据：软件名、版本、架构、依赖、安装脚本、校验信息

零基础类比：Windows 下载 `.exe` 安装包，双击后安装；Linux 下载 `.rpm` 或 `.deb` 软件包，通过包管理器安装。

常见软件包格式：

| 发行版体系                       | 包格式 | 底层工具 | 高层包管理器      |
| -------------------------------- | ------ | -------- | ----------------- |
| Red Hat/CentOS/Fedora/Rocky/Alma | `.rpm` | `rpm`    | `yum` / `dnf`     |
| Debian/Ubuntu                    | `.deb` | `dpkg`   | `apt` / `apt-get` |

重点区别：

- `.rpm` / `.deb` 是“包文件格式”；
- `rpm` / `dpkg` 是“本地包安装工具”；
- `yum` / `dnf` / `apt` 是“联网管理工具”，能从软件源下载软件并自动处理依赖。

## 1.2 软件包的本质

软件包本质上可以理解为：

```text
软件包 = 文件集合 + 安装规则 + 版本信息 + 依赖信息 + 校验/签名信息
```

例如你安装 `nginx`，系统并不是随便把一个文件放进去，而是会把不同文件放到标准目录：

```text
/usr/sbin/nginx              # nginx 主程序
/etc/nginx/nginx.conf        # nginx 配置文件
/usr/lib/systemd/system/...  # systemd 服务管理文件
/var/log/nginx/...           # 日志目录
```

这就是 Linux 软件包管理的核心价值：**按照统一规范安装、升级、查询和卸载软件。**

## 1.3 为什么不建议初学者直接源码安装

源码安装通常流程是：

```bash
tar -zxvf xxx.tar.gz
cd xxx
./configure
make
sudo make install
```

它的问题是：

- 依赖需要自己找，报错通常很抽象；
- 编译耗时长；
- 安装路径可能不统一；
- 卸载困难，因为系统不知道你手动放了哪些文件；
- 后续升级、回滚、审计都麻烦。

所以企业服务器更常用：

```bash
sudo yum install nginx
sudo apt install nginx
```

包管理器会自动完成：查找软件、下载包、分析依赖、安装文件、记录安装数据库。

## 1.4 软件包与包管理器的关系

软件包和包管理器的关系可以这样理解：

```text
软件包：货物
软件源：仓库/超市
包管理器：快递员 + 仓库管理员 + 安装工人
系统本地数据库：购物记录/安装记录
```

包管理器能做的事情：

- 搜索软件：`yum search nginx`
- 查询软件信息：`yum info nginx`
- 安装软件：`yum install nginx`
- 升级软件：`yum update nginx`
- 卸载软件：`yum remove nginx`
- 处理依赖：自动安装软件运行需要的库
- 管理软件源：启用、禁用、添加 repo
- 记录历史：`yum history`

## 1.5 主流包管理器对比

| 包管理器 | 适用发行版                   | 包格式 | 常用命令                    | 特点                                  |
| -------- | ---------------------------- | ------ | --------------------------- | ------------------------------------- |
| `yum`    | CentOS 7、RHEL 7 等          | `.rpm` | `yum install/remove/update` | 经典 RPM 高层包管理器                 |
| `dnf`    | Fedora、RHEL 8+、Rocky 8+ 等 | `.rpm` | `dnf install/remove/update` | yum 的后继者，依赖解析更好            |
| `apt`    | Ubuntu、Debian               | `.deb` | `apt install/remove/update` | Debian 系主流包管理器                 |
| `rpm`    | RPM 系                       | `.rpm` | `rpm -ivh/-qa/-e`           | 只处理本地 rpm 包，不自动联网解决依赖 |
| `dpkg`   | Debian 系                    | `.deb` | `dpkg -i/-l/-r`             | 只处理本地 deb 包，不自动联网解决依赖 |

注意：很多新系统里，`yum` 可能只是 `dnf` 的兼容入口。例如 RHEL 8 之后的 yum 基于 DNF 技术，部分系统中 `yum` 和 `dnf` 命令效果接近。

## 1.6 本节企业面试题

### 题 1：Linux 中软件包和包管理器有什么区别？

答：软件包是软件文件的打包结果，里面包含程序、配置、依赖元数据等；包管理器是管理软件包的工具，负责搜索、安装、升级、卸载和自动处理依赖。比如 `.rpm` 是软件包格式，`yum`/`dnf` 是包管理器。

### 题 2：为什么生产环境更推荐 yum/apt 安装，而不是源码 make install？

答：因为包管理器安装的软件路径规范、依赖可自动解决、安装记录可查询、卸载升级方便、支持安全更新和签名校验；源码安装虽然灵活，但依赖和卸载管理麻烦，容易造成系统不可控。

### 题 3：rpm 和 yum 有什么区别？

答：`rpm` 是 RPM 包的底层管理工具，适合安装本地 `.rpm` 文件，但不会自动从远程仓库处理复杂依赖；`yum` 是高层包管理器，基于软件源仓库工作，能自动下载目标软件及依赖包。

# 02 Linux 软件生态：软件源、镜像源、依赖关系

## 2.1 Linux 软件安装的底层流程

使用包管理器安装一个软件，本质流程是：

```text
用户输入安装命令
        ↓
读取本机 repo 配置
        ↓
访问软件源仓库
        ↓
查找目标软件包
        ↓
解析依赖关系
        ↓
下载目标包和依赖包
        ↓
执行安装事务
        ↓
写入本地 rpm 数据库
        ↓
安装完成
```

例如：

```bash
sudo yum install nginx
```

yum 大致会做这些事：

1. 去 `/etc/yum.repos.d/` 读取 repo 配置；
2. 去 repo 指向的服务器查找 `nginx`；
3. 发现 nginx 可能依赖 `pcre`、`openssl-libs`、`zlib` 等；
4. 下载 nginx 和依赖包；
5. 调用 rpm 机制安装；
6. 把安装信息记录到本地 RPM 数据库中。

## 2.2 什么是软件源 Repository

软件源英文叫 **Repository**，简称 **repo**。它是一个远程软件仓库，里面放了大量软件包和元数据。

repo 通常包含：

- 软件包文件：很多 `.rpm` 包；
- 元数据：有哪些软件、版本是多少、依赖是什么；
- 签名信息：用于验证软件包是否可信；
- 分组信息：比如开发工具组、桌面环境组。

CentOS/RHEL 系 repo 配置文件通常放在：

```bash
/etc/yum.repos.d/
```

文件后缀通常是：

```bash
.repo
```

例如：

```bash
/etc/yum.repos.d/CentOS-Base.repo
/etc/yum.repos.d/epel.repo
/etc/yum.repos.d/nginx.repo
```

## 2.3 软件源的分类

| 类型     | 说明             | 例子                             | 优点                 | 风险             |
| -------- | ---------------- | -------------------------------- | -------------------- | ---------------- |
| 官方源   | 发行版官方维护   | base、updates、extras            | 稳定、安全、兼容性好 | 软件版本可能偏旧 |
| 第三方源 | 社区或厂商维护   | EPEL、Nginx 官方源、MySQL 官方源 | 软件更多、版本更新   | 可能与官方包冲突 |
| 镜像源   | 官方源的同步副本 | 阿里云源、清华源、中科大源       | 国内下载快           | 同步延迟或源过期 |
| 本地源   | 内网自己搭建     | 公司内部 yum 仓库                | 适合离线内网         | 需要维护成本     |

## 2.4 什么是镜像源

镜像源不是“新的软件仓库”，而是把官方仓库复制到国内服务器上。这样国内机器访问更快。

例如官方源在国外，访问很慢；换成阿里云、清华、中科大镜像后，下载速度明显提升。

常见镜像站：

| 镜像源                 | 特点                         |
| ---------------------- | ---------------------------- |
| 阿里云开源镜像站       | 覆盖全、速度快，企业环境常见 |
| 清华大学开源软件镜像站 | 文档清晰、稳定可靠           |
| 中科大开源镜像站       | 资源全面                     |
| 网易开源镜像站         | 使用简单                     |
| 北京交通大学镜像站     | 配置指南较清楚               |

## 2.5 软件依赖关系是什么

依赖关系英文叫 **Dependency**。意思是：一个软件运行时需要另一个软件、库或组件。

例如 nginx 可能依赖：

```text
nginx
 ├── pcre：正则表达式支持
 ├── zlib：压缩支持
 ├── openssl-libs：HTTPS 加密支持
 └── systemd-units：服务管理支持
```

如果手动安装，就可能出现：

```text
error while loading shared libraries: libxxx.so: cannot open shared object file
```

这表示程序运行时找不到依赖库。

包管理器的价值就是自动解析：

```text
你只说：我要 nginx
yum 帮你算：还需要 A、B、C、D
```

## 2.6 依赖关系的常见问题

### 2.6.1 依赖缺失

表现：

```text
Requires: xxx
No package xxx available
```

原因：

- 没有启用对应源；
- 软件源过旧；
- 系统版本不匹配；
- 架构不匹配，例如 x86_64 和 aarch64。

### 2.6.2 依赖冲突

表现：

```text
conflicts with file from package ...
requires xxx >= version
```

原因：

- 装了多个第三方源；
- 新旧版本混装；
- 手动 rpm 安装破坏了依赖；
- 发行版版本不匹配。

### 2.6.3 循环依赖

两个或多个包互相依赖。现代 yum/dnf/apt 通常能处理，手动 rpm 安装时容易遇到。

## 2.7 CentOS 系统替换 yum 源

> 说明：以下以 CentOS 7 为例。实际生产中需注意 CentOS 7 已经停止官方维护，建议新环境优先使用 Rocky Linux、AlmaLinux、RHEL、Ubuntu LTS 等仍在维护的系统。

### 2.7.1 备份原 repo 文件

```bash
sudo mkdir -p /etc/yum.repos.d/backup
sudo mv /etc/yum.repos.d/*.repo /etc/yum.repos.d/backup/
```

解释：

- `mkdir -p`：目录不存在就创建，存在也不报错；
- `/etc/yum.repos.d/`：yum 源配置目录；
- `mv *.repo backup/`：把旧源配置移走，避免新旧源冲突。

### 2.7.2 下载新的 repo 配置

```bash
sudo curl -o /etc/yum.repos.d/CentOS-Base.repo http://mirrors.aliyun.com/repo/Centos-7.repo
```

解释：

- `curl -o 文件名 URL`：把 URL 内容下载到指定文件；
- `CentOS-Base.repo`：yum 源配置文件；
- 如果系统没有 `curl`，可以换成 `wget`。

### 2.7.3 清理旧缓存并生成新缓存

```bash
sudo yum clean all
sudo yum makecache
```

解释：

- `yum clean all`：清理旧的软件源元数据和包缓存；
- `yum makecache`：根据新源重新生成缓存；
- 换源后一定要执行这两步，否则可能还是用旧缓存。

### 2.7.4 验证 yum 源

```bash
sudo yum repolist
```

如果能看到 `base`、`extras`、`updates` 等仓库，并且状态是可用，说明配置基本成功。

## 2.8 Ubuntu 系统替换 apt 源

Ubuntu 使用的是 apt，不是 yum。apt 源主配置文件通常是：

```bash
/etc/apt/sources.list
```

备份：

```bash
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
```

更新缓存：

```bash
sudo apt update
```

注意：Ubuntu 不建议盲目直接覆盖 `sources.list`，因为不同 Ubuntu 版本代号不同，例如 `jammy`、`noble`。更稳妥的做法是去镜像站选择对应 Ubuntu 版本生成配置。

## 2.9 本节企业面试题

### 题 1：什么是 yum 源？为什么换源后要执行 yum clean all 和 yum makecache？

答：yum 源是远程软件仓库，里面保存软件包和依赖元数据。换源后，本地旧缓存可能还指向旧仓库，所以要先 `yum clean all` 清掉旧缓存，再 `yum makecache` 根据新 repo 重新生成元数据缓存。

### 题 2：为什么 yum 能自动解决依赖？

答：因为软件包元数据中记录了依赖关系，yum 会读取 repo 中的软件包元数据，构建依赖关系图，计算出安装目标软件所需的所有依赖包，然后统一下载和安装。

### 题 3：官方源、第三方源、镜像源有什么区别？

答：官方源由发行版维护，稳定安全；第三方源由社区或厂商维护，软件更多但可能带来冲突；镜像源是官方源或第三方源的同步副本，主要解决访问速度问题。

# 03 yum 前置条件与基本命令模型

## 3.1 使用 yum 的前置条件

使用 yum 前最好确认三件事：

### 3.1.1 网络是否通

```bash
ping www.baidu.com -c 3
```

解释：

- `ping`：测试网络连通；
- `-c 3`：只发送 3 次包，避免一直 ping。

如果 `ping` 域名失败但 `ping 8.8.8.8` 成功，通常是 DNS 问题。

### 3.1.2 是否有权限

安装、卸载、升级软件会修改系统目录，通常需要 root 权限：

```bash
sudo yum install nginx
```

如果当前就是 root 用户，可以不加 `sudo`。

### 3.1.3 软件源是否可用

```bash
yum repolist
```

如果输出仓库列表并显示软件包数量，说明源可用。

## 3.2 yum 命令基本结构

```bash
yum [选项] 子命令 [软件包名]
```

常见形式：

```bash
yum list
yum info nginx
sudo yum install nginx
sudo yum remove nginx
sudo yum update nginx
```

常用选项：

| 选项                 | 含义              | 示例                                |
| -------------------- | ----------------- | ----------------------------------- |
| `-y`                 | 自动回答 yes      | `yum install -y nginx`              |
| `--nogpgcheck`       | 跳过 GPG 签名检查 | 临时排查可用，不建议长期用          |
| `--enablerepo=源名`  | 临时启用某个源    | `yum --enablerepo=epel install xxx` |
| `--disablerepo=源名` | 临时禁用某个源    | `yum --disablerepo=epel update`     |
| `--downloadonly`     | 只下载不安装      | 离线安装准备常用                    |
| `--downloaddir=目录` | 指定下载目录      | 配合 `--downloadonly`               |

## 3.3 yum 的常见子命令

| 子命令             | 作用               |
| ------------------ | ------------------ |
| `list`             | 列出软件包         |
| `search`           | 搜索软件包         |
| `info`             | 查看软件包详细信息 |
| `install`          | 安装软件           |
| `remove` / `erase` | 卸载软件           |
| `update`           | 更新软件           |
| `check-update`     | 检查可更新软件     |
| `deplist`          | 查看依赖           |
| `repolist`         | 查看软件源         |
| `clean`            | 清理缓存           |
| `makecache`        | 生成缓存           |
| `history`          | 查看历史事务       |
| `groupinstall`     | 安装软件组         |

## 3.4 本节企业面试题

### 题 1：yum install -y 中的 -y 是什么意思？

答：`-y` 表示自动确认 yes，不需要人工输入确认。脚本部署中常用，但生产环境升级核心组件时要谨慎，因为它会跳过人工确认步骤。

### 题 2：yum repolist 有什么作用？

答：用于查看当前启用的软件源仓库。如果安装软件失败，第一步就应该看 `yum repolist`，确认源是否存在、是否启用、是否能正常加载。

# 04 yum 查询类操作

## 4.1 列出所有软件包

```bash
yum list
```

这个命令会列出所有可见软件包，包括已安装和可安装的软件包。输出很多，通常结合 `grep` 使用：

```bash
yum list | grep nginx
```

## 4.2 搜索软件包

```bash
yum search nginx
```

和 `yum list | grep nginx` 的区别：

- `yum list | grep nginx`：偏向按包名过滤；
- `yum search nginx`：会在名称和描述中搜索，范围更宽。

## 4.3 查看软件包详细信息

```bash
yum info nginx
```

常见字段：

| 字段          | 含义              |
| ------------- | ----------------- |
| `Name`        | 软件包名          |
| `Arch`        | 架构，例如 x86_64 |
| `Version`     | 上游版本号        |
| `Release`     | 发行版打包版本    |
| `Size`        | 包大小            |
| `Repo`        | 来自哪个仓库      |
| `Summary`     | 简短描述          |
| `Description` | 详细说明          |

## 4.4 查询已安装软件包

```bash
yum list installed
```

结合过滤：

```bash
yum list installed | grep gcc
```

也可以用 rpm：

```bash
rpm -qa | grep gcc
```

区别：

- `yum list installed` 通过 yum 展示；
- `rpm -qa` 直接查询 RPM 数据库，更底层。

## 4.5 查询软件依赖

```bash
yum deplist nginx
```

输出通常包括：

```text
dependency: libpcre.so.1()(64bit)
provider: pcre.x86_64
```

解释：

- `dependency`：需要什么依赖；
- `provider`：哪个包能提供这个依赖。

## 4.6 查询某个命令属于哪个包

这是面试和实际排错很常用的补充命令：

```bash
yum provides */semanage
```

或者：

```bash
yum whatprovides */semanage
```

作用：当你知道命令名但不知道要装哪个包时，用它查。

例如 `semanage` 命令找不到，可能需要安装：

```bash
sudo yum install policycoreutils-python
```

## 4.7 查询本地 RPM 包信息

如果你已经有一个 rpm 文件：

```bash
rpm -qpi package.rpm
```

查看这个 rpm 会安装哪些文件：

```bash
rpm -qpl package.rpm
```

## 4.8 本节企业面试题

### 题 1：如何查看某个软件是否已经安装？

答：

```bash
yum list installed | grep 软件名
rpm -qa | grep 软件名
```

如果能查到，说明已经安装。

### 题 2：如何知道 nginx 依赖哪些包？

答：

```bash
yum deplist nginx
```

它会列出 nginx 需要的依赖以及由哪些包提供这些依赖。

### 题 3：命令 not found，但不知道该安装哪个包，怎么办？

答：

```bash
yum provides */命令名
```

它可以查出哪个软件包提供这个命令。

# 05 yum 安装类操作

## 5.1 安装单个软件包

```bash
sudo yum install lrzsz
```

解释：

- `sudo`：使用管理员权限；
- `yum install`：安装；
- `lrzsz`：软件包名，用于 rz/sz 文件传输。

安装过程中 yum 会提示：

```text
Is this ok [y/d/N]:
```

输入 `y` 表示确认安装。

## 5.2 静默安装

```bash
sudo yum install -y gcc
```

`-y` 表示自动确认。适合脚本化安装，例如：

```bash
sudo yum install -y git vim wget curl net-tools
```

## 5.3 一次安装多个软件包

```bash
sudo yum install -y gcc gcc-c++ make
```

注意：CentOS 中 C++ 编译器包名通常是 `gcc-c++`，不是所有系统都叫 `g++`。Ubuntu 中常见命令是：

```bash
sudo apt install -y g++
```

## 5.4 安装开发工具组

很多时候编译软件需要一组工具，可以安装软件组：

```bash
sudo yum groupinstall -y "Development Tools"
```

它通常会安装 gcc、make、binutils 等构建工具。

## 5.5 安装扩展源中的软件

有些软件官方源没有，需要先启用 EPEL：

```bash
sudo yum install -y epel-release
sudo yum install -y nginx
```

EPEL 是 Extra Packages for Enterprise Linux，给 RHEL/CentOS 等系统提供额外软件包。

## 5.6 安装本地 rpm 包

如果你已经下载好了 rpm 文件：

```bash
sudo yum localinstall -y xxx.rpm
```

或者新一些系统也支持：

```bash
sudo yum install -y ./xxx.rpm
```

和 `rpm -ivh xxx.rpm` 相比，`yum localinstall` 更推荐，因为它会尝试从已配置的软件源中解决依赖。

## 5.7 本节企业面试题

### 题 1：yum install 和 rpm -ivh 安装本地包有什么区别？

答：`rpm -ivh` 只安装本地 rpm 包，遇到依赖缺失会直接报错；`yum install ./xxx.rpm` 或 `yum localinstall xxx.rpm` 会尝试结合软件源自动解决依赖，更适合实际使用。

### 题 2：为什么安装 nginx 前有时要先安装 epel-release？

答：因为某些 CentOS 版本的默认源可能没有 nginx 或版本较旧，EPEL 提供额外软件包。安装 `epel-release` 后会添加 EPEL repo，yum 才能从该源找到 nginx 等软件。

# 06 yum 升级类操作

## 6.1 升级指定软件包

```bash
sudo yum update -y nginx
```

作用：只升级 nginx 及其必要依赖。

## 6.2 升级所有软件包

```bash
sudo yum update -y
```

作用：升级系统中所有可升级的软件包。

生产环境注意：

- 不要随便全量升级核心服务器；
- 升级前先备份；
- 先在测试环境验证；
- 关注内核、glibc、openssl、systemd 等基础组件；
- 如果升级了内核，通常需要重启后才会使用新内核。

## 6.3 检查可升级软件包

```bash
yum check-update
```

说明：

- 只检查，不真正升级；
- 常用于运维巡检脚本；
- 可以提前查看哪些包会被升级。

## 6.4 update 和 upgrade 的区别

在 yum 中：

```bash
yum update
yum upgrade
```

很多场景下效果接近。传统区别是 `upgrade` 更倾向于处理 obsoletes（废弃替换包）逻辑。日常更常用 `yum update`。

在 apt 中：

```bash
sudo apt update       # 更新软件包索引，不升级软件
sudo apt upgrade      # 升级软件，不主动删除包
sudo apt full-upgrade # 可安装/删除包以完成升级
```

## 6.5 安全更新补充

企业服务器常关心安全更新。可安装安全插件后查看：

```bash
sudo yum install -y yum-plugin-security
yum updateinfo list security
sudo yum update --security
```

注意：不同发行版支持情况不同，新系统用 dnf 的安全更新命令更多。

## 6.6 本节企业面试题

### 题 1：yum update -y 能不能在生产环境随便执行？

答：不建议。`yum update -y` 会自动升级所有可升级软件，可能引入版本变化、服务重启、配置变化或兼容性问题。生产环境应先 `yum check-update`，评估影响，在测试环境验证后再升级。

### 题 2：apt update 和 apt upgrade 有什么区别？

答：`apt update` 只是更新本地软件包索引，相当于刷新“软件列表”；`apt upgrade` 才是真正升级已安装软件包。

# 07 yum 卸载与依赖清理

## 7.1 卸载指定软件包

```bash
sudo yum remove -y lrzsz
```

`remove` 会卸载软件包，并根据依赖情况处理相关包。

等价命令：

```bash
sudo yum erase -y lrzsz
```

## 7.2 卸载多个软件包

```bash
sudo yum remove -y nginx httpd
```

## 7.3 清理无用依赖

```bash
sudo yum autoremove -y
```

作用：删除不再被其他软件需要的依赖包。

注意：

- 不要盲目在重要服务器上执行；
- 先看将要删除的包；
- 有些包看似无用，但可能被手动程序依赖。

## 7.4 卸载软件但保留配置的问题

不同软件包的卸载策略不同。一般来说：

- 程序文件会删除；
- 配置文件可能保留或生成 `.rpmsave`、`.rpmnew`；
- 数据目录不一定删除，例如数据库数据通常不会随便删除。

这是保护数据的设计，避免卸载软件时误删重要数据。

## 7.5 rpm 强制卸载的风险

```bash
sudo rpm -e --nodeps 包名
```

`--nodeps` 表示忽略依赖强制卸载。这个命令危险，可能导致依赖它的软件无法运行。面试中可以提，但生产中尽量避免。

## 7.6 本节企业面试题

### 题 1：yum remove 会不会删除配置文件和数据？

答：不一定。软件包管理器通常会删除软件包安装的文件，但为了避免误删用户数据，某些配置文件或数据目录可能被保留，或者被重命名为 `.rpmsave` 等形式。

### 题 2：rpm -e --nodeps 为什么危险？

答：它会忽略依赖强制删除包，可能破坏其他软件的运行环境，造成命令缺失、库缺失或服务启动失败。

# 08 yum 缓存管理

## 8.1 yum 缓存是什么

yum 为了加快查询和安装，会把软件源元数据和下载过的软件包缓存在本地。常见缓存内容包括：

- 软件包列表；
- 依赖元数据；
- 仓库信息；
- 下载过的 rpm 包。

## 8.2 清理所有缓存

```bash
sudo yum clean all
```

常见场景：

- 换源后；
- 软件源元数据异常；
- yum 提示元数据校验失败；
- 安装时反复访问旧源；
- 磁盘空间不足。

## 8.3 只清理软件包缓存

```bash
sudo yum clean packages
```

作用：删除已下载的软件包缓存。

## 8.4 只清理元数据缓存

```bash
sudo yum clean metadata
```

作用：删除仓库元数据，适合 repo 信息异常时使用。

## 8.5 重新生成缓存

```bash
sudo yum makecache
```

换源后常用组合：

```bash
sudo yum clean all
sudo yum makecache
sudo yum repolist
```

## 8.6 本节企业面试题

### 题 1：yum clean all 和 yum makecache 分别干什么？

答：`yum clean all` 清理旧缓存，包括软件源元数据和包缓存；`yum makecache` 重新从当前 repo 下载元数据并生成新缓存。换源后通常两个一起用。

### 题 2：yum 安装软件时一直访问旧地址怎么办？

答：先检查 `/etc/yum.repos.d/` 中 repo 配置，再执行 `yum clean all && yum makecache`，确保本地缓存更新。

# 09 yum 软件源 repo 管理

## 9.1 查看已启用软件源

```bash
yum repolist
```

## 9.2 查看所有软件源，包括禁用源

```bash
yum repolist all
```

输出中的状态：

```text
enabled   # 已启用
disabled  # 已禁用
```

## 9.3 repo 配置文件位置

```bash
/etc/yum.repos.d/
```

查看：

```bash
ls /etc/yum.repos.d/
```

## 9.4 repo 文件基本结构

一个典型 repo 文件如下：

```ini
[nginx-stable]
name=nginx stable repo
baseurl=http://nginx.org/packages/centos/$releasever/$basearch/
gpgcheck=1
enabled=1
gpgkey=https://nginx.org/keys/nginx_signing.key
```

字段解释：

| 字段             | 含义                           |
| ---------------- | ------------------------------ |
| `[nginx-stable]` | repo ID，必须唯一              |
| `name`           | 仓库描述名称                   |
| `baseurl`        | 仓库地址                       |
| `$releasever`    | 系统版本变量，例如 7、8、9     |
| `$basearch`      | 架构变量，例如 x86_64、aarch64 |
| `gpgcheck=1`     | 开启 GPG 签名校验              |
| `enabled=1`      | 启用该源                       |
| `gpgkey`         | GPG 公钥地址                   |

## 9.5 启用或禁用软件源

需要安装工具：

```bash
sudo yum install -y yum-utils
```

禁用 EPEL：

```bash
sudo yum-config-manager --disable epel
```

启用 EPEL：

```bash
sudo yum-config-manager --enable epel
```

临时启用某个源安装：

```bash
sudo yum --enablerepo=epel install -y nginx
```

临时禁用某个源：

```bash
sudo yum --disablerepo=epel update
```

## 9.6 添加第三方源的正确姿势

不要随便复制网上来路不明的 repo。推荐流程：

1. 找官方文档；
2. 确认系统版本和架构；
3. 导入 GPG key；
4. 添加 repo；
5. `yum makecache`；
6. `yum repolist` 验证。

## 9.7 本节企业面试题

### 题 1：repo 文件中的 enabled=0 和 enabled=1 分别是什么意思？

答：`enabled=1` 表示启用该软件源，yum 会从该源查询和安装软件；`enabled=0` 表示禁用，默认不会使用，但可通过 `--enablerepo` 临时启用。

### 题 2：gpgcheck 的作用是什么？

答：`gpgcheck=1` 表示安装软件包时检查 GPG 签名，确认软件包来源可信且未被篡改。生产环境不建议长期关闭。

### 题 3：为什么第三方源可能导致依赖冲突？

答：因为第三方源可能提供和官方源同名但版本不同的软件包，yum 解析依赖时可能混用不同源的软件，导致版本不兼容或文件冲突。

# 10 yum 常见问题排查

## 10.1 问题一：Another app is currently holding the yum lock

### 10.1.1 现象

安装时提示：

```text
Another app is currently holding the yum lock
```

意思是另一个 yum/rpm 进程正在运行，当前 yum 无法获取锁。

### 10.1.2 原因

- 另一个终端正在执行 yum；
- 系统自动更新进程占用 yum；
- 上一次 yum 异常退出，残留锁文件；
- rpm 数据库正在被其他进程使用。

### 10.1.3 排查步骤

先查进程：

```bash
ps aux | grep yum
ps aux | grep rpm
```

如果确实有 yum 正在运行，不要直接 kill，先确认它是不是正在正常安装。

如果确认是卡死进程，再结束：

```bash
sudo kill -9 PID
```

删除残留锁：

```bash
sudo rm -f /var/run/yum.pid
```

### 10.1.4 面试回答模板

yum lock 是为了防止多个 yum/rpm 事务同时修改 rpm 数据库。如果多个安装进程同时运行，可能导致数据库损坏，所以 yum 会加锁。排查时先看是否有 yum/rpm 进程，确认没有正常任务后再清理锁文件。

## 10.2 问题二：yum 搜索不到软件包

### 10.2.1 现象

```text
No package nginx available.
Error: Nothing to do
```

### 10.2.2 可能原因

- 软件包名写错；
- 当前源没有这个包；
- 没启用 EPEL 或第三方源；
- 系统版本太旧或已经 EOL；
- 架构不匹配；
- 缓存过期。

### 10.2.3 排查命令

检查源：

```bash
yum repolist
```

搜索：

```bash
yum search nginx
yum list | grep nginx
```

清缓存：

```bash
sudo yum clean all
sudo yum makecache
```

安装 EPEL：

```bash
sudo yum install -y epel-release
```

查询由哪个包提供命令：

```bash
yum provides */命令名
```

## 10.3 问题三：yum 依赖冲突

### 10.3.1 现象

```text
Error: Package: xxx requires: yyy >= 1.2
Error: xxx conflicts with yyy
```

### 10.3.2 常见原因

- 混用了多个第三方源；
- 手动 rpm 安装过软件；
- 软件包版本跨发行版；
- CentOS/RHEL 大版本不匹配；
- 架构不匹配；
- 旧版本依赖没有升级。

### 10.3.3 排查思路

查看包来自哪个源：

```bash
yum info 包名
```

查看重复包：

```bash
package-cleanup --dupes
```

查看依赖问题：

```bash
package-cleanup --problems
```

需要安装：

```bash
sudo yum install -y yum-utils
```

临时禁用可疑源：

```bash
sudo yum --disablerepo=epel install 包名
```

## 10.4 问题四：Could not resolve host

### 10.4.1 现象

```text
Could not resolve host: mirrors.xxx.com
```

### 10.4.2 原因

DNS 解析失败。

### 10.4.3 排查

测试 IP 连通：

```bash
ping 8.8.8.8 -c 3
```

测试域名解析：

```bash
ping www.baidu.com -c 3
```

查看 DNS 配置：

```bash
cat /etc/resolv.conf
```

临时添加 DNS：

```bash
sudo sh -c 'echo "nameserver 8.8.8.8" >> /etc/resolv.conf'
```

注意：某些系统由 NetworkManager 管理 DNS，直接改 `/etc/resolv.conf` 可能重启后失效。

## 10.5 问题五：GPG key 校验失败

### 10.5.1 现象

```text
Public key for xxx.rpm is not installed
```

### 10.5.2 原因

yum 开启了 GPG 校验，但系统没有导入对应仓库的公钥。

### 10.5.3 解决

从官方地址导入 key：

```bash
sudo rpm --import https://example.com/RPM-GPG-KEY
```

不推荐长期使用：

```bash
sudo yum install xxx --nogpgcheck
```

因为这会跳过签名校验，降低安全性。

## 10.6 本节企业面试题

### 题 1：yum 被锁住怎么办？

答：先用 `ps aux | grep yum` 和 `ps aux | grep rpm` 查是否有正在运行的 yum/rpm 进程。如果是正常任务，等待完成；如果确认卡死，kill 对应 PID，再删除 `/var/run/yum.pid`。不能一上来就删锁，避免破坏 rpm 数据库。

### 题 2：yum 找不到包怎么排查？

答：先确认包名是否正确，再看 `yum repolist` 是否有可用源，然后 `yum clean all && yum makecache` 更新缓存；如果默认源没有，考虑启用 EPEL 或官方第三方源；还要确认系统版本和架构是否匹配。

### 题 3：依赖冲突怎么处理？

答：先查软件来自哪个源，检查是否混用了多个第三方源；再用 `yum deplist`、`package-cleanup --problems` 排查依赖；必要时禁用冲突源、升级依赖、使用官方匹配版本，避免强制 `rpm --nodeps`。

# 11 yum 进阶：历史记录与离线安装

## 11.1 yum history 查看历史

```bash
yum history
```

输出类似：

```text
ID | Command line        | Date and time | Action(s) | Altered
10 | install -y nginx    | ...           | Install   | 15
9  | remove -y lrzsz     | ...           | Erase     | 1
```

字段解释：

| 字段           | 含义                         |
| -------------- | ---------------------------- |
| `ID`           | 事务编号                     |
| `Command line` | 当时执行的命令               |
| `Action(s)`    | 动作：Install、Update、Erase |
| `Altered`      | 影响的软件包数量             |

## 11.2 查看某次历史详情

```bash
yum history info 10
```

可以看到这次事务安装、升级、删除了哪些包。

## 11.3 回滚某次操作

```bash
sudo yum history undo 9 -y
```

含义：撤销 ID 为 9 的事务。

注意：

- 回滚不一定 100% 成功；
- 如果旧版本包已经从源中删除，可能无法回滚；
- 如果依赖环境变化很大，也可能失败；
- 生产环境回滚前要看 `yum history info ID`。

## 11.4 redo 和 rollback

重新执行某次事务：

```bash
sudo yum history redo ID
```

回滚到某个事务状态：

```bash
sudo yum history rollback ID
```

区别：

- `undo ID`：撤销某一次事务；
- `redo ID`：重做某一次事务；
- `rollback ID`：回滚到某个历史点，影响范围更大，风险也更大。

## 11.5 离线安装场景

企业常见场景：

- 内网服务器不能访问外网；
- 生产环境禁止联网；
- 需要在多台机器重复部署；
- 需要固定软件版本。

基本思路：

```text
有网机器下载 rpm 包和依赖
        ↓
拷贝到离线机器
        ↓
离线安装所有 rpm
```

## 11.6 下载软件包及其依赖

方法一：使用 yum 的 downloadonly：

```bash
mkdir -p /tmp/yum-packages
sudo yum install -y --downloadonly --downloaddir=/tmp/yum-packages lrzsz
```

方法二：使用 yumdownloader：

```bash
sudo yum install -y yum-utils
mkdir -p /tmp/yum-packages
yumdownloader --resolve --destdir=/tmp/yum-packages lrzsz
```

解释：

- `--downloadonly`：只下载，不安装；
- `--downloaddir`：指定下载目录；
- `--resolve`：下载依赖。

## 11.7 离线安装 rpm 包

进入目录：

```bash
cd /tmp/yum-packages
```

安装：

```bash
sudo rpm -ivh *.rpm
```

更推荐：

```bash
sudo yum localinstall -y *.rpm
```

如果离线机器也有本地 repo，可以更好地解析依赖。

## 11.8 搭建本地 yum 仓库补充

安装工具：

```bash
sudo yum install -y createrepo
```

创建元数据：

```bash
createrepo /opt/localrepo
```

创建 repo 文件：

```ini
[localrepo]
name=Local Repository
baseurl=file:///opt/localrepo
enabled=1
gpgcheck=0
```

刷新缓存：

```bash
sudo yum clean all
sudo yum makecache
```

## 11.9 本节企业面试题

### 题 1：yum history undo 有什么作用？

答：用于撤销某次 yum 事务，例如撤销一次安装或卸载。但它依赖当前软件源中仍能找到需要的版本和依赖，生产环境使用前要先查看历史详情并评估风险。

### 题 2：内网机器不能联网，如何安装软件？

答：在同版本、同架构、有网络的机器上使用 `yum install --downloadonly` 或 `yumdownloader --resolve` 下载目标包和依赖，然后拷贝到内网机器，用 `yum localinstall` 或本地 yum 仓库安装。

### 题 3：为什么离线安装必须注意系统版本和架构一致？

答：因为 rpm 包和依赖与发行版版本、CPU 架构强相关。CentOS 7 的包不一定适合 CentOS 8；x86_64 的包不能直接装到 aarch64 系统。

# 12 apt、dnf、rpm、dpkg 补充对比

## 12.1 dnf 与 yum

DNF 是 yum 的下一代替代工具。很多新系统中推荐使用 dnf，例如 Fedora、RHEL 8+、Rocky 8+、Alma 8+。

常用命令基本对应：

| yum                 | dnf                          |
| ------------------- | ---------------------------- |
| `yum install nginx` | `dnf install nginx`          |
| `yum remove nginx`  | `dnf remove nginx`           |
| `yum update`        | `dnf upgrade` / `dnf update` |
| `yum info nginx`    | `dnf info nginx`             |
| `yum repolist`      | `dnf repolist`               |
| `yum history`       | `dnf history`                |

面试表达：**yum 是经典工具，dnf 是后继者；在较新的 RHEL 系系统中，yum 可能是 dnf 的兼容别名。**

## 12.2 apt 与 yum

| 操作     | CentOS/RHEL yum     | Ubuntu/Debian apt   |
| -------- | ------------------- | ------------------- |
| 更新索引 | `yum makecache`     | `apt update`        |
| 安装软件 | `yum install nginx` | `apt install nginx` |
| 卸载软件 | `yum remove nginx`  | `apt remove nginx`  |
| 升级软件 | `yum update nginx`  | `apt upgrade`       |
| 搜索软件 | `yum search nginx`  | `apt search nginx`  |
| 查看信息 | `yum info nginx`    | `apt show nginx`    |
| 清理缓存 | `yum clean all`     | `apt clean`         |

注意：`apt update` 不等于 `yum update`。  
`apt update` 只是更新软件列表，而 `yum update` 是升级软件包。

## 12.3 rpm 与 dpkg

| 操作               | RPM 系               | Debian 系            |
| ------------------ | -------------------- | -------------------- |
| 查看已安装包       | `rpm -qa`            | `dpkg -l`            |
| 安装本地包         | `rpm -ivh xxx.rpm`   | `dpkg -i xxx.deb`    |
| 卸载包             | `rpm -e 包名`        | `dpkg -r 包名`       |
| 查看包文件列表     | `rpm -ql 包名`       | `dpkg -L 包名`       |
| 查询文件属于哪个包 | `rpm -qf /path/file` | `dpkg -S /path/file` |

## 12.4 常见易混点

### 12.4.1 yum update 和 apt update

- `yum update`：升级软件；
- `apt update`：更新软件包索引，不升级软件。

### 12.4.2 yum install 和 rpm -ivh

- `yum install`：可联网解决依赖；
- `rpm -ivh`：只安装本地包，不自动解决依赖。

### 12.4.3 remove 和 purge

Ubuntu 中：

```bash
sudo apt remove nginx
sudo apt purge nginx
```

区别：

- `remove`：卸载软件，通常保留配置；
- `purge`：卸载软件并删除配置。

yum 没有完全对应的 `purge` 语义。

# 14 企业面试题与参考答案

## 14.1 基础概念类

### 题 1：Linux 中安装软件有哪些方式？

答：常见方式有三类：第一，用包管理器安装，比如 yum、dnf、apt，这是最推荐的方式；第二，安装本地包，比如 rpm 或 dpkg；第三，源码编译安装，比如 configure、make、make install。企业环境一般优先使用包管理器，因为依赖、升级、卸载、审计都更规范。

### 题 2：软件包里通常包含什么？

答：包含可执行文件、动态库、配置文件、服务文件、文档、安装脚本和元数据。元数据记录了软件名称、版本、架构、依赖和签名信息。

### 题 3：为什么 yum 比 rpm 更方便？

答：rpm 只能处理本地 rpm 包，依赖需要自己解决；yum 可以从 repo 下载软件包，自动解析和安装依赖，并维护安装历史和缓存。

## 14.2 软件源与依赖类

### 题 4：yum repo 配置文件在哪？

答：通常在 `/etc/yum.repos.d/` 目录下，文件后缀是 `.repo`。

### 题 5：repo 文件中 baseurl、enabled、gpgcheck 分别是什么意思？

答：`baseurl` 表示仓库地址；`enabled` 表示是否启用该源，1 是启用，0 是禁用；`gpgcheck` 表示是否校验软件包 GPG 签名，1 是校验，能提升安全性。

### 题 6：为什么换源后还安装失败？

答：可能是缓存没有更新、repo 配置错误、DNS 不通、系统版本不匹配、源已停止维护，或者目标包不在该源中。排查时先执行 `yum clean all && yum makecache`，再看 `yum repolist`。

### 题 7：如何判断一个包来自哪个 yum 源？

答：

```bash
yum info 包名
```

看输出中的 `Repo` 字段。

## 14.3 查询与安装类

### 题 8：如何查找 nginx 是否可安装？

答：

```bash
yum search nginx
yum list | grep nginx
```

### 题 9：如何查看 nginx 已经安装了哪些文件？

答：

```bash
rpm -ql nginx
```

### 题 10：如何知道 `/usr/sbin/nginx` 属于哪个软件包？

答：

```bash
rpm -qf /usr/sbin/nginx
```

### 题 11：如何查找哪个包提供某个命令？

答：

```bash
yum provides */命令名
```

例如：

```bash
yum provides */semanage
```

## 14.4 升级与卸载类

### 题 12：yum update 和 yum install 的区别？

答：`yum install` 用于安装未安装的软件包；`yum update` 用于升级已安装的软件包。如果软件未安装，某些情况下 update 不会像 install 一样安装它。

### 题 13：生产环境能不能直接 yum update -y？

答：不建议。它会自动升级所有可升级软件，可能导致服务行为变化、依赖变化或重启需求。生产环境应先 `yum check-update`，评估升级内容，在测试环境验证，再灰度升级。

### 题 14：卸载软件用什么命令？

答：

```bash
sudo yum remove -y 软件名
```

或者：

```bash
sudo yum erase -y 软件名
```

## 14.5 故障排查类

### 题 15：yum 提示 Another app is currently holding the yum lock 怎么办？

答：先查是否有 yum/rpm 进程正在运行：

```bash
ps aux | grep yum
ps aux | grep rpm
```

如果是正常安装任务，等待完成；如果确认卡死，kill 对应 PID，再删除 `/var/run/yum.pid`。不要不检查就直接删锁。

### 题 16：yum 安装提示 No package available 怎么排查？

答：先确认包名，再查看 `yum repolist`，然后 `yum clean all && yum makecache`。如果默认源没有，启用 EPEL 或添加官方第三方源。还要检查系统版本、CPU 架构和 repo 地址是否匹配。

### 题 17：yum 依赖冲突怎么排查？

答：先看包来自哪个源，确认是否混用第三方源；用 `yum deplist` 查看依赖，用 `package-cleanup --problems` 检查问题；必要时禁用冲突源或使用发行版匹配的软件包，不建议强制 `rpm --nodeps`。

### 题 18：yum 报 DNS 解析失败怎么办？

答：先 `ping IP` 测网络，再 `ping 域名` 测 DNS。如果 IP 通但域名不通，检查 `/etc/resolv.conf` 或 NetworkManager DNS 配置。

## 14.6 离线安装类

### 题 19：无外网服务器如何安装软件？

答：在同系统版本、同架构、有网络的机器上下载 rpm 包和依赖：

```bash
yumdownloader --resolve --destdir=/tmp/packages 软件名
```

然后拷贝到离线服务器，用：

```bash
sudo yum localinstall -y *.rpm
```

更规范的做法是搭建本地 yum 仓库。

### 题 20：为什么离线安装不能随便从网上下载 rpm？

答：因为 rpm 包与系统版本、依赖版本、CPU 架构强相关。下载不匹配的包可能导致依赖冲突或服务无法启动，还可能有安全风险。

## 14.7 对比类高频题

### 题 21：yum 和 apt 有什么区别？

答：yum/dnf 用于 RPM 系发行版，如 CentOS、RHEL、Fedora、Rocky、Alma；apt 用于 Debian 系发行版，如 Ubuntu、Debian。yum 管理 `.rpm` 包，apt 管理 `.deb` 包。命令形式不同，但核心目标都是安装、升级、卸载和解决依赖。

### 题 22：yum 和 dnf 有什么区别？

答：dnf 是 yum 的下一代替代工具，依赖解析和性能更好，Fedora 和 RHEL 8+ 等新系统更推荐 dnf。很多新系统中 `yum` 可能作为兼容命令指向 dnf。

### 题 23：apt update 和 yum update 为什么不能直接类比？

答：`apt update` 只是更新本地软件包索引，不升级软件；`yum update` 是升级软件包。apt 中真正升级软件通常是 `apt upgrade` 或 `apt full-upgrade`。

# 15 复习总结

## 15.1 一句话总结

Linux 软件包管理器的核心是：**通过软件源仓库获取软件包，根据元数据自动解析依赖，并用统一方式完成安装、升级、卸载、查询、缓存和历史管理。**

## 15.2 必背命令

```bash
yum repolist
yum search 软件名
yum info 软件名
yum install -y 软件名
yum remove -y 软件名
yum update -y 软件名
yum check-update
yum clean all
yum makecache
yum deplist 软件名
yum history
yum provides */命令名
rpm -qa | grep 软件名
rpm -ql 软件名
rpm -qf 文件路径
```

## 15.3 必背排查顺序

当 yum 安装失败时，按这个顺序排查：

```text
1. 网络是否通：ping IP / ping 域名
2. DNS 是否正常：cat /etc/resolv.conf
3. yum 源是否可用：yum repolist
4. 包名是否正确：yum search / yum list | grep
5. 缓存是否异常：yum clean all && yum makecache
6. 是否缺少第三方源：EPEL / 官方 repo
7. 是否版本或架构不匹配：系统版本、x86_64/aarch64
8. 是否依赖冲突：yum deplist / package-cleanup
9. 是否 yum 锁冲突：ps aux | grep yum
```

## 15.4 面试最后拔高表达

如果面试官问你“你怎么理解 Linux 包管理器”，可以这样答：

> 我理解包管理器不只是安装软件的命令，它背后是一套软件分发体系。软件包里有程序文件、配置文件、依赖元数据和签名信息；repo 提供软件包和元数据；yum/dnf/apt 读取 repo 后解析依赖，生成安装事务，再调用底层 rpm/dpkg 完成安装，同时维护本地安装数据库。这样系统才能统一查询、升级、卸载、回滚和排错。生产环境中我会关注 repo 来源、安全签名、版本兼容、缓存更新、依赖冲突和离线部署。
